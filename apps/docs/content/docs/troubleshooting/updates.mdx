title: HALAI desktop updates
description: Recover from a stuck download or restart and understand supported update paths.

HALAI checks the update feed configured in the installed build. Open [HALAI releases](https://github.com/empire-mind/HALAI/releases) to find the release notes, platform packages and supported upgrade paths. Check the architecture, signing information and checksum before using a manual installer.

| Build | What the button does |
|---|---|
| macOS, Windows, Linux AppImage | **Restart to update** — the app replaces itself and reopens. An AppImage is always rewritten at the path you launch, so your launcher, symlink or dock pin keeps working. |
| Ubuntu `.deb` (and rpm/pacman) | **Install** downloads and verifies the package, then copies the install command. Review the package path and run the command yourself with the appropriate permissions. |

## The download keeps spinning

Leave the app open long enough for one complete attempt, then quit and reopen it. A failed differential update should fall back to the full package. If the download remains stuck, open the [HALAI release notes](https://github.com/empire-mind/HALAI/releases). Use a manual package once the notes confirm an upgrade path for your installed build.

On macOS, **Preparing update** is a separate step after the download finishes. macOS must stage the update before **Restart to update** becomes available. A completed download does not mean this preparation is finished.

If an update fails, its error stays visible. If a restart is taking longer than expected, quit the app completely before trying again.

## Restart to update does nothing

Quit HALAI completely and launch it again. If the version stayed the same, preserve your workspace data and follow the upgrade instructions for that version. Refer to [Data and backups](/docs/self-hosting/data-and-backups) before replacing an app bundle or changing the installation identity.

## Report an update failure

Open **App settings → General → Diagnostics → Export Diagnostics…**. Include your operating system, the currently installed version, the target version, and whether the failure happened during download, preparation, or restart. Newer builds include a bounded, redacted updater log alongside the server and desktop logs. Review the exported file before sharing it privately with support.

## No terminal opened

Open a terminal, paste the copied command, and check that its path names the verified package for the intended version. If the clipboard was overwritten, reopen the update card. For a manual Ubuntu install, use the exact package from the release notes with `apt-get`, which resolves dependencies.

## Verify the installed version

Open **App settings** and check the displayed version against the published HALAI release. A source build can be identified by the revision recorded when it was built.
